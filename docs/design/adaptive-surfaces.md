# Adaptive surface architecture

The 0.3.0 table skins captured complete materials but fixed every layer to the 1000 × 600 desktop scene. `PokerTable` also couples that scene to normalized HTML overlay anchors. Changing its CSS aspect ratio cannot recompute a stadium or preserve round studs, insets, textures and lettering. Exporting constants alone leaves consumers responsible for duplicating the renderer.

The implementation keeps SVG and the captured six skin definitions, then separates artwork from overlay composition. A public `TableSurface` uses tight outer-rail bounds, numeric width/height and one material scale. The existing `PokerTable` keeps its exact canvas and anchor contracts and uses the same internal `TableArtwork` renderer.

The alternatives considered were nonuniform SVG stretching, rotating the canonical desktop, a second CSS material renderer, and making PokerTable itself own responsive gameplay layouts. Stretching deforms details; rotation cannot express arbitrary proportions and rotates text/lighting; a second renderer recreates the original maintenance problem; moving gameplay layout into the library conflicts with consumer-owned anchors. An additive artwork-only entry gives consumers the missing control with fewer public concepts.

The existing deterministic skin generator records geometry placement semantics separately from material data: inset contours, edge-anchored ornaments, perimeter studs and tiled textures. Runtime adaptation only calculates those placements. Paint data and vector assets are shared; there is no renderer for each theme/orientation pair. Identity geometry reuses the original captured layer array, preserving every default desktop pixel, including the original pattern phase and stud positions. Adapted textures repeat regular cells and adapted studs use perimeter distances. Ornament paths use uniform transforms; lettering remains outlined SVG.

Material definitions are deduplicated once per theme at module initialization. Geometry is memoized per instance and primitive geometry props; CSS resizing does not recalculate it. The artwork component also avoids rerendering when only consumer overlays change. Texture DOM size is constant and stud count is capped at 512. No resize observer, font loader, canvas, image download, runtime SVG parser or new dependency is introduced.

Default regressions use full PNG captures rendered from the unmodified 0.3.0 renderer in `tooling/assets/reference/tables/v0.3.0-*.png`, compared at identical dimensions and with identical rasterization settings. Independent Penpot Classic/Royal references remain in use. Additional unit and browser checks cover all themes, portrait/landscape/square/intermediate dimensions, insets/radii, material scaling, round perimeter studs, tiled texture references, instance isolation, responsive sizing, props/refs and consumer-owned interaction. Browser screenshots are retained by CI for visual inspection.
